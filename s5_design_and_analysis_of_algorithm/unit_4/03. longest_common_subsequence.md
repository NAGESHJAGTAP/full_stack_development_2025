# Longest Common Subsequence (LCS)
## 1. What is the "Longest Common Subsequence" Problem?

### 1.1 Simple Meaning

A **subsequence** of a string is what is left after deleting **some letters (maybe none)** while keeping the remaining letters in their **original order**. The letters do **not** have to be next to each other.

Given two strings, a **common subsequence** is a string that is a subsequence of **both** of them. The **Longest Common Subsequence (LCS)** problem asks: *what is the longest common subsequence of the two strings?*

It sounds simple, but a natural first idea -- "scan the strings and grab every match you meet" -- **does not always work**. This note shows why, and then solves the problem correctly with **Dynamic Programming** (see the Introduction to Dynamic Programming note). The table-filling idea is similar to the one in the Making Change Problem and 0/1 Knapsack Problem notes.

### 1.2 Everyday Analogy

Alice and Bob each wrote down the **order in which they played songs** at a party. Every letter stands for one song:

```
Alice :  A  G  G  T  A  B
Bob   :  G  X  T  X  A  Y  B
```

They ask: *what is the longest list of songs that **both** of them played, in the **same order**?* The songs do not have to be played back-to-back -- other songs may come in between. Songs `G`, `T`, `A`, `B` were played by both, in that order. That is a common subsequence of length 4, and (as we will see) the longest one.

### 1.3 The Problem Statement

| Part | Meaning |
| :-- | :-- |
| **Input** | Two strings `X` (length `m`) and `Y` (length `n`) |
| **Assumption** | A subsequence keeps the **order** of the letters, and its letters may have gaps between them in the original string |
| **Goal** | Find the **longest** string that is a subsequence of both `X` and `Y` |
| **Output** | The **length** of the LCS, and the LCS string itself |

Two things to remember: the answer is never negative (if the strings share no letter, the LCS is the empty string, with length `0`), and the answer string is **not always unique** -- Section 4.8 shows two strings with two different longest answers.

### 1.4 What is a Subsequence?

For every letter of a string there are only two choices: **keep** it or **delete** it. Here is how `GTAB` is a subsequence of both of our strings:

```
X :   A   G   G   T   A   B
      x   .   x   .   .   .        x = deleted, . = kept
                                   delete positions 1 and 3  -> G T A B

Y :   G   X   T   X   A   Y   B
      .   x   .   x   .   x   .
                                   delete positions 2, 4 and 6 -> G T A B
```

A subsequence is **not** the same as a substring. A **substring** must be a block of letters that are **next to each other**:

| Text | Piece | Substring? | Subsequence? |
| :-- | :-: | :-: | :-: |
| `AGGTAB` | `GTA` | Yes (positions 3 to 5) | Yes |
| `GXTXAYB` | `GTAB` | **No** (the letters are not next to each other) | **Yes** |
| `AGGTAB` | `BTA` | No | **No** (the order is wrong: in `AGGTAB` the `B` comes after the `T`) |

Because each letter is kept or deleted, a string with `n` letters has `2^n` ways to choose its letters:

| Letters `n` | Ways to Keep or Delete (`2^n`) |
| :-: | :-: |
| 3 (for example `ABC`) | 8 |
| 6 (our `AGGTAB`) | 64 |
| 10 | 1,024 |
| 20 | 1,048,576 |
| 30 | 1,073,741,824 |

Some of these ways give the same string when letters repeat (`AGGTAB` has 64 ways but only 46 different strings, because there are two `G`s). The number of ways is still what makes trying everything hopeless for long strings.

### 1.5 Our Running Example

**`X = AGGTAB`** (`m = 6`) and **`Y = GXTXAYB`** (`n = 7`)

| Position | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| :-- | :-: | :-: | :-: | :-: | :-: | :-: | :-: |
| **`X`** | A | G | G | T | A | B | |
| **`Y`** | G | X | T | X | A | Y | B |

Here is **every** common subsequence of the two strings, sorted by length. (There are 16, counting the empty string.)

| Length | How Many | The Common Subsequences |
| :-: | :-: | :-- |
| 0 | 1 | the empty string |
| 1 | 4 | `A`, `B`, `G`, `T` |
| 2 | 6 | `AB`, `GA`, `GB`, `GT`, `TA`, `TB` |
| 3 | 4 | `GAB`, `GTA`, `GTB`, `TAB` |
| **4** | **1** | **`GTAB`** |
| 5 or more | 0 | none |

So the correct answer is **length 4**, and the LCS is **`GTAB`**. Notice that it is the **only** one of length 4.

Listing everything is only possible because the strings are tiny. The rest of this note builds a smart method, using this same example throughout.

### 1.6 Where Is It Used?

| Application | What the LCS Idea Does |
| :-- | :-- |
| **File Comparison (diff tools)** | Finds the lines two versions of a file have in common, in order, so only the differences are shown |
| **Version Control and Merging** | Helps decide which parts of two edited copies are the same |
| **DNA and Protein Comparison** | Measures how similar two genetic sequences are by their longest shared pattern |
| **Plagiarism and Document Similarity** | A long common subsequence of words suggests two texts are related |
| **Spell Checking and Text Correction** | Related ideas measure how many edits turn one word into another (Section 5.2) |

## 2. First Idea -- The Greedy Method

### 2.1 The Greedy Rule

A **greedy** method makes the choice that **looks best right now** and never changes its mind. For LCS, a natural rule is the **first fit**:

> Take the letters of one string from left to right. For each letter, look for its **earliest** match in the other string **after the last match**. If there is one, take it and never undo it.

We can walk along `X` and search in `Y`, or the other way round. We will try both.

### 2.2 Greedy Step by Step

**Walk along `X`, search in `Y`** (`X = AGGTAB`, `Y = GXTXAYB`):

| Step | Letter of `X` | Search `Y` From | Found At | Action | Taken So Far |
| :-: | :-: | :-: | :-: | :-- | :-: |
| 1 | A (`x1`) | `y1` | `y5` | Take it | `A` |
| 2 | G (`x2`) | `y6` | not found (`y6 = Y`, `y7 = B`) | Skip | `A` |
| 3 | G (`x3`) | `y6` | not found | Skip | `A` |
| 4 | T (`x4`) | `y6` | not found | Skip | `A` |
| 5 | A (`x5`) | `y6` | not found | Skip | `A` |
| 6 | B (`x6`) | `y6` | `y7` | Take it | `AB` |

Greedy ends with **`AB`**, length **2**. But Section 1.5 showed that `GTAB` has length **4**. So greedy gave a **wrong (not the longest)** answer.

**Walk along `Y`, search in `X`:**

| Step | Letter of `Y` | Search `X` From | Found At | Action | Taken So Far |
| :-: | :-: | :-: | :-: | :-- | :-: |
| 1 | G (`y1`) | `x1` | `x2` | Take it | `G` |
| 2 | X (`y2`) | `x3` | not found | Skip | `G` |
| 3 | T (`y3`) | `x3` | `x4` | Take it | `GT` |
| 4 | X (`y4`) | `x5` | not found | Skip | `GT` |
| 5 | A (`y5`) | `x5` | `x5` | Take it | `GTA` |
| 6 | Y (`y6`) | `x6` | not found | Skip | `GTA` |
| 7 | B (`y7`) | `x6` | `x6` | Take it | `GTAB` |

This direction finds `GTAB` (length 4), the right answer -- but only by **luck**. Section 2.3 shows a pair of strings where **both** directions fail.

### 2.3 Both Directions Can Fail

Take `X = ABAC` and `Y = CBA`. The best common subsequence is `BA` (length 2):

| Direction | What Happens | Result |
| :-- | :-- | :-: |
| **Walk along `X`** | `A` matches the only `A` of `Y` (`y3`), which is the **last** letter of `Y`; nothing can come after it, so `B`, `A`, `C` are all skipped | `A` (length 1) |
| **Walk along `Y`** | `C` matches the only `C` of `X` (`x4`), which is the **last** letter of `X`; nothing can come after it, so `B` and `A` are skipped | `C` (length 1) |
| **Best possible** | `B` (`x2`, `y2`) then `A` (`x3`, `y3`) | `BA` (length 2) |

### 2.4 Greedy and the Best Answer, Drawn as Matches

Each line joins a letter of `X` to the letter of `Y` it is matched with (`x2` means position 2 of `X`, and so on). Matched pairs must keep the same order in both strings:

```
 Greedy (walk along x)               Best (from the DP table)

 x1  A ------ A  y5                  x2  G ------ G  y1
 x6  B ------ B  y7                  x4  T ------ T  y3
                                     x5  A ------ A  y5
                                     x6  B ------ B  y7

 length 2                            length 4
```

Greedy grabbed the `A` at `x1` and matched it with the `A` at `y5`. That match uses up almost all of `Y`, so only the `B` was left to add. The best answer skips that early `A` completely.

### 2.5 Greedy Code

```cpp
#include <iostream>
#include <string>
using namespace std;

// Greedy rule: take the letters of a one by one, from left to right.
// For each letter, look for its EARLIEST match in b after the last match.
// If there is one, take it and never undo it.
string firstFit(const string& a, const string& b) {
    string result = "";
    int last = -1;                               // position in b of the last letter we matched

    for (int i = 0; i < (int)a.size(); i++) {
        for (int j = last + 1; j < (int)b.size(); j++) {
            if (a[i] == b[j]) {                  // earliest match after the last one
                result = result + a[i];
                last = j;
                break;                           // stop searching for this letter
            }
        }
    }
    return result;
}

// Runs the greedy rule in both directions on one pair of strings
void tryPair(const string& x, const string& y) {
    string r1 = firstFit(x, y);                  // walk along x, search in y
    string r2 = firstFit(y, x);                  // walk along y, search in x

    cout << "x = " << x << ", y = " << y << endl;
    cout << "   walk along x: " << (r1 == "" ? "(empty)" : r1) << "  (length " << r1.size() << ")" << endl;
    cout << "   walk along y: " << (r2 == "" ? "(empty)" : r2) << "  (length " << r2.size() << ")" << endl;
}

int main() {
    tryPair("AGGTAB", "GXTXAYB");                // our main example
    tryPair("ABAC", "CBA");                      // a pair where BOTH directions fail
    tryPair("ABCBDAB", "BDCAB");
    tryPair("ABC", "XYZ");

    return 0;
}
```

**Verified Output:**
```
x = AGGTAB, y = GXTXAYB
   walk along x: AB  (length 2)
   walk along y: GTAB  (length 4)
x = ABAC, y = CBA
   walk along x: A  (length 1)
   walk along y: C  (length 1)
x = ABCBDAB, y = BDCAB
   walk along x: AB  (length 2)
   walk along y: BDAB  (length 4)
x = ABC, y = XYZ
   walk along x: (empty)  (length 0)
   walk along y: (empty)  (length 0)
```

How to read the output:

- **First pair:** walking along `x` gives `AB` (Section 2.2, first table); walking along `y` gives `GTAB` (Section 2.2, second table).
- **Second pair (`ABAC`, `CBA`):** both directions give length 1, but the best is 2 (Section 2.3).
- **Third and fourth pairs:** used again in Section 4.9, where we compare greedy with the DP answer.

### 2.6 Why Greedy Fails

Greedy takes the **first** match it sees and **cannot go back**. An early match can use up letters that a longer common subsequence needed later. For `X = AGGTAB`, matching the first `A` with `y5` threw away every letter of `Y` that comes before `y5` (`G`, `X`, `T`, `X`), and those held most of the answer.

> **Important:** the first-fit scan is fine as a **fast guess**, but it **cannot be trusted** to find the longest answer. We need a method that is **always correct**.

### 2.7 Where the First-Fit Scan IS Correct

The same scan **does** work for a simpler question: *is a given string a subsequence of another string?* Taking the earliest match always leaves the most room for the remaining letters. For example, with `Y = GXTXAYB`:

| Question | Scan | Answer |
| :-- | :-- | :-: |
| Is `GTAB` a subsequence of `Y`? | `G` at `y1`, `T` at `y3`, `A` at `y5`, `B` at `y7` | **Yes** |
| Is `GBT` a subsequence of `Y`? | `G` at `y1`, `B` at `y7`, then no `T` after `y7` | **No** |

Checking one candidate is easy. The hard part of LCS is that there are far too many candidates, and greedy cannot pick the best one.

## 3. Thinking Recursively -- Finding the Recurrence

### 3.1 The Key Idea

Look at the **last letters** of the two strings, `x_m` and `y_n`. There are only two possibilities:

| Case | What It Means | What Is Left to Solve |
| :-: | :-- | :-- |
| **1. The last letters are equal** | They can be matched with each other | `1` + the LCS of `X` without its last letter and `Y` without its last letter |
| **2. The last letters differ** | At least one of the two last letters is **not used** by the best answer | The **larger** of: the LCS of `X` without its last letter and `Y`, or the LCS of `X` and `Y` without its last letter |

**Why Case 1 is safe.** Suppose both last letters are `c`. A best answer must end with `c`: if it did not, then it only uses letters **before** the two last letters, so we could add `c` at the end and get a longer common subsequence -- which is impossible. So it ends with `c`, and what comes before is the best answer for the shorter strings.

**Why Case 2 works.** If a best answer used `x_m`, it would have to match it with some earlier letter of `Y` (it cannot match `y_n`, because the letters differ), so `y_n` is unused. In the same way, if it used `y_n`, then `x_m` is unused. So at least one of them is unused and can be thrown away. We do not know which one, so we **try both** and keep the better result.

### 3.2 The Recurrence

Let `L(i, j)` = the length of the LCS of the **first `i` letters of `X`** and the **first `j` letters of `Y`**.

```
L(0, j) = 0                                   (X is empty: nothing in common)
L(i, 0) = 0                                   (Y is empty: nothing in common)

L(i, j) = 1 + L(i-1, j-1)                     if x_i = y_j      (last letters match)
L(i, j) = max( L(i-1, j) , L(i, j-1) )        if x_i != y_j     (drop one last letter)
```

The answer to the whole problem is `L(m, n)`.

### 3.3 Working It Out by Hand

For the 6-by-7 running example the full recursion makes 346 calls (Section 3.6), too many to write out. So we first work the recurrence by hand on a **tiny pair**: `X = ABC` and `Y = CBA` (`x1 = A`, `x2 = B`, `x3 = C` and `y1 = C`, `y2 = B`, `y3 = A`). We want `L(3, 3)`. Here are all the calls that are not trivial, from the smallest to the answer. (Calls with an empty string, such as `L(0, 1)` or `L(2, 0)`, are all `0`.)

| Call | Last Letters `x_i`, `y_j` | Equal? | Calculation | Value |
| :-: | :-: | :-: | :-- | :-: |
| `L(1,1)` | A and C | No | `max( L(0,1) , L(1,0) )` = max(0, 0) = 0 | **0** |
| `L(1,3)` | A and A | Yes | `1 + L(0,2)` = 1 + 0 = 1 | **1** |
| `L(2,2)` | B and B | Yes | `1 + L(1,1)` = 1 + 0 = 1 | **1** |
| `L(2,3)` | B and A | No | `max( L(1,3) , L(2,2) )` = max(1, 1) = 1 | **1** |
| `L(3,1)` | C and C | Yes | `1 + L(2,0)` = 1 + 0 = 1 | **1** |
| `L(3,2)` | C and B | No | `max( L(2,2) , L(3,1) )` = max(1, 1) = 1 | **1** |
| `L(3,3)` | C and A | No | `max( L(2,3) , L(3,2) )` = max(1, 1) = 1 | **1** |

So `L(3, 3) = 1`: the strings `ABC` and `CBA` share no pair of letters in the same order, but any single letter is a common subsequence.

### 3.4 The Recurrence as Plain Recursion

We can turn the recurrence straight into a recursive function:

```cpp
#include <iostream>
#include <string>
using namespace std;

long long callCount = 0;   // counts how many times lcs() is called

// Length of the LCS of the first i letters of x and the first j letters of y
int lcs(const string& x, const string& y, int i, int j) {
    callCount++;

    if (i == 0 || j == 0)                          // base case: one of the strings is empty
        return 0;

    if (x[i - 1] == y[j - 1])                      // last letters are equal: they match
        return 1 + lcs(x, y, i - 1, j - 1);

    int dropX = lcs(x, y, i - 1, j);               // otherwise drop the last letter of x ...
    int dropY = lcs(x, y, i, j - 1);               // ... or drop the last letter of y
    return (dropX > dropY) ? dropX : dropY;
}

int main() {
    string x = "AGGTAB";
    string y = "GXTXAYB";
    cout << "x = " << x << ", y = " << y << ": LCS length = "
         << lcs(x, y, (int)x.size(), (int)y.size()) << "   calls = " << callCount << endl;

    callCount = 0;
    string a = "ABC";
    string b = "CBA";
    cout << "x = " << a << ", y = " << b << ": LCS length = "
         << lcs(a, b, (int)a.size(), (int)b.size()) << "   calls = " << callCount << endl;
    cout << endl;

    // Growth test: worst case, the two strings have NO letter in common
    int sizes[] = {4, 6, 8, 10, 12, 14};
    for (int s = 0; s < 6; s++) {
        int n = sizes[s];
        string px = string(n, 'A');                // AAAA...A
        string py = string(n, 'B');                // BBBB...B
        callCount = 0;
        int result = lcs(px, py, n, n);
        cout << "n = " << n << " letters each: LCS length = " << result
             << "   calls = " << callCount << endl;
    }

    return 0;
}
```

**Verified Output:**
```
x = AGGTAB, y = GXTXAYB: LCS length = 4   calls = 346
x = ABC, y = CBA: LCS length = 1   calls = 15

n = 4 letters each: LCS length = 0   calls = 139
n = 6 letters each: LCS length = 0   calls = 1847
n = 8 letters each: LCS length = 0   calls = 25739
n = 10 letters each: LCS length = 0   calls = 369511
n = 12 letters each: LCS length = 0   calls = 5408311
n = 14 letters each: LCS length = 0   calls = 80233199
```

How to read the output:

- **First line:** the running example gives `4`, using **346 calls**.
- **Second line:** the tiny pair `ABC` / `CBA` gives `1`, using **15 calls** -- the tree of Section 3.5.
- **The `n = ...` lines:** the worst case, where the strings share **no** letter (`AAAA...` against `BBBB...`), so every call has to try both choices. The `calls` column grows very fast. Section 3.6 explains it.

### 3.5 The Recursion Tree for L(3, 3)

Here is every call made while computing `L(3, 3)` for `ABC` / `CBA`. The first child of a call is `L(i-1, j)` and the second child is `L(i, j-1)`; when the last letters match there is a single child `L(i-1, j-1)`. A call marked `*` repeats a subproblem that **already appeared earlier** in the tree:

```
L(3,3)                    C vs A: differ
+-- L(2,3)                B vs A: differ
|   +-- L(1,3)            A vs A: match
|   |   +-- L(0,2)        empty string: 0
|   +-- L(2,2)            B vs B: match
|       +-- L(1,1)        A vs C: differ
|           +-- L(0,1)    empty string: 0
|           +-- L(1,0)    empty string: 0
+-- L(3,2)                C vs B: differ
    +-- L(2,2)            B vs B: match   * repeat
    |   +-- L(1,1)        A vs C: differ   * repeat
    |       +-- L(0,1)    empty string: 0   * repeat
    |       +-- L(1,0)    empty string: 0   * repeat
    +-- L(3,1)            C vs C: match
        +-- L(2,0)        empty string: 0
```

`* repeat` = this exact `(i, j)` pair was already solved earlier in the tree, so the same work is done again.

| Kind of Call | How Many |
| :-- | :-: |
| First-time calls that make a real choice (the 7 rows of the table in Section 3.3) | 7 |
| First-time calls that stop at once (an empty string) | 4 |
| Repeated calls (a pair already seen earlier in the tree) | 4 |
| **Total calls** | **15** |

The 15 calls solve only **11 different** subproblems (7 + 4), so **4 calls are pure repetition**: `L(2,2)` and the three calls below it. This matches exactly the `calls = 15` printed in Section 3.4.

### 3.6 How Bad Does It Get?

For our running example, the plain recursion needs **346 calls**, but they only involve **32 different** `(i, j)` pairs. The table of Section 4 has `(6+1) x (7+1) = 56` cells (42 of them need a calculation).

| Plain Recursion Calls | Different `(i, j)` Pairs Among Them | Table Cells `(m+1)(n+1)` |
| :-: | :-: | :-: |
| 346 | 32 | 56 |

So 314 of the 346 calls only repeat work that was already done. And this is a tiny example. In the **worst case** (no letter in common, `n` letters each) the program of Section 3.4 printed:

| Letters `n` in Each String | Calls by Plain Recursion | Table Cells `(n+1)(n+1)` |
| :-: | :-: | :-: |
| 4 | 139 | 25 |
| 6 | 1,847 | 49 |
| 8 | 25,739 | 81 |
| 10 | 369,511 | 121 |
| 12 | 5,408,311 | 169 |
| 14 | 80,233,199 | 225 |

Every 2 extra letters in each string make the number of calls roughly **14 times bigger**. That is **exponential growth**. (In this worst case the number of calls is exactly `2 x C(2n, n) - 1`, where `C(2n, n)` counts the ways to choose `n` things out of `2n`.) Meanwhile the number of different `(i, j)` pairs -- the table cells -- grows slowly.

### 3.7 Why Can This Problem Be Solved with Dynamic Programming?

| # | Point | What We See in LCS | Why It Matters for DP |
| :-: | :-- | :-- | :-- |
| **1** | **Smaller subproblems of the same kind** | `L(i, j)` is built from `L(i-1, j-1)`, `L(i-1, j)` and `L(i, j-1)` | We have a recurrence |
| **2** | **Optimal substructure** | A best answer for `(i, j)` contains a best answer for a smaller pair (Section 3.1) | It is safe to build answers from best smaller answers |
| **3** | **The subproblems overlap** | The same pair is reached by different routes: dropping the last letter of `X` and then of `Y`, or of `Y` and then of `X`, both end at `(i-1, j-1)`. The running example made 346 calls for 32 pairs | Saving an answer avoids repeated work |
| **4** | **Only a few different subproblems** | At most `(m + 1)(n + 1)` pairs, although there may be millions of calls | A small table can hold every answer |
| **5** | **A subproblem always has the same answer** | `L(2, 2)` for `ABC` / `CBA` is always `1` | Safe to save and reuse |
| **6** | **There is a natural order** | Cell `(i, j)` needs only cells with a smaller `i` or `j` | Fill the table row by row |

**Conclusion:** LCS has everything DP needs. The next section builds the table.

## 4. Dynamic Programming Solution -- The Table

### 4.1 The Table

We use the classic table that also lets us find the **LCS string itself**:

```
L[i][j] = the length of the LCS of the first i letters of X
          and the first j letters of Y
```

- **Rows** `i = 0, 1, ..., m`: row `i` means "use the first `i` letters of `X`" (row 0 is the empty string).
- **Columns** `j = 0, 1, ..., n`: column `j` means "use the first `j` letters of `Y`" (column 0 is the empty string).
- The answer to the whole problem is the **bottom-right cell**, `L[m][n]`.

This is the recurrence `L(i, j)` of Section 3.2 written as a table.

### 4.2 The Five Steps Applied

| # | Step | For LCS |
| :-: | :-- | :-- |
| **1** | Define the subproblem | `L[i][j]` = LCS length of the first `i` letters of `X` and the first `j` letters of `Y` |
| **2** | Write the recurrence | Match: diagonal plus 1. No match: the larger of up and left (Section 4.3) |
| **3** | Set the base cases | `L[0][j] = 0` for every `j`, and `L[i][0] = 0` for every `i` |
| **4** | Choose the order | Row by row from `i = 1`, and left to right inside a row |
| **5** | Find the final answer | `L[m][n]` |

### 4.3 The Rules for Filling a Cell

Compare the letters `x_i` and `y_j` (in code, `x[i-1]` and `y[j-1]`, because strings count from 0).

| Situation | Rule | Meaning |
| :-- | :-- | :-- |
| `i = 0` or `j = 0` | `L[i][j] = 0` | An empty string has nothing in common with anything |
| `x_i = y_j` | `L[i][j] = L[i-1][j-1] + 1` | **Match:** take the letter and add 1 to the **diagonal** cell |
| `x_i != y_j` | `L[i][j] = max( L[i-1][j] , L[i][j-1] )` | **No match:** take the larger of the cell **above** and the cell to the **left** |

```
                       column j-1             column j
                +---------------------+---------------------+
row i-1         |     L[i-1][j-1]     |      L[i-1][j]      |
                |       DIAGONAL      |          UP         |
                |   used on a match,  |  used on a mismatch |
                |        add 1        |                     |
                +---------------------+---------------------+
row i           |      L[i][j-1]      |       L[i][j]       |
                |         LEFT        |   <-- the cell we   |
                |  used on a mismatch |     are filling     |
                +---------------------+---------------------+
```

- **Diagonal** `L[i-1][j-1]`: used on a **match**. Both letters are used up, so we continue with one letter less in each string.
- **Up** `L[i-1][j]`: used on a mismatch. It means "throw away the last letter of `X`".
- **Left** `L[i][j-1]`: used on a mismatch. It means "throw away the last letter of `Y`".

The last row, `0 1 1 2 2 3 3 4`, gives the LCS length of the **whole** `X` against every prefix of `Y`. For example, `AGGTAB` against the first 5 letters of `Y` (`GXTXA`) has an LCS of length 3 (`GTA`).

### 4.6 Finding the LCS String

The number `4` tells us the **length**. To find the **string**, we walk back from the bottom-right cell `L[6][7]` until we reach row 0 or column 0:

- If `x_i = y_j`, this letter is **part of the LCS**: write it down and move **diagonally** up-left.
- Otherwise, move to the **larger** of the cell above and the cell to the left. If they are equal, we move **up** (either choice works).

Letters are found from the **last** one to the **first**, so each new letter is written in front of the ones we already have.

| Step | Position `(i, j)` | Letters `x_i`, `y_j` | Decision | LCS So Far |
| :-: | :-: | :-: | :-- | :-: |
| 1 | `(6, 7)` | B and B | Equal: **take `B`** (`x6`, `y7`); move diagonally to `(5, 6)` | `B` |
| 2 | `(5, 6)` | A and Y | Different: up `L[4][6]` = 2, left `L[5][5]` = 3: left is larger, move left to `(5, 5)` | `B` |
| 3 | `(5, 5)` | A and A | Equal: **take `A`** (`x5`, `y5`); move diagonally to `(4, 4)` | `AB` |
| 4 | `(4, 4)` | T and X | Different: up `L[3][4]` = 1, left `L[4][3]` = 2: left is larger, move left to `(4, 3)` | `AB` |
| 5 | `(4, 3)` | T and T | Equal: **take `T`** (`x4`, `y3`); move diagonally to `(3, 2)` | `TAB` |
| 6 | `(3, 2)` | G and X | Different: up `L[2][2]` = 1, left `L[3][1]` = 1: **tie**, move up to `(2, 2)` | `TAB` |
| 7 | `(2, 2)` | G and X | Different: up `L[1][2]` = 0, left `L[2][1]` = 1: left is larger, move left to `(2, 1)` | `TAB` |
| 8 | `(2, 1)` | G and G | Equal: **take `G`** (`x2`, `y1`); move diagonally to `(1, 0)` | `GTAB` |
| 9 | `(1, 0)` | -- | `j = 0`: nothing left in `Y` to match, stop (the unmatched `A` at `x1` is simply not used) | **`GTAB`** |

As a picture, here is how the two strings line up. Each column is one step of the walk (the walk itself runs from the right end to the left end). A `|` joins two matched letters, and a `-` marks a letter that has no partner:

```
x :  A  G  -  G  T  -  A  -  B
        |        |     |     |
y :  -  G  X  -  T  X  A  Y  B
```

The alignment has exactly **9 columns**, which is `m + n - LCS = 6 + 7 - 4`: each matched pair shares one column, and every unmatched letter takes a column of its own.

### 4.7 The Code

```cpp
#include <iostream>
#include <iomanip>
#include <string>
#include <algorithm>
using namespace std;

int L[51][51];   // L[i][j] = LCS length of the first i letters of x and the first j letters of y

// Builds the table, prints it, finds one LCS, and returns it.
// Assumes both strings have at most 50 letters.
string solve(const string& x, const string& y) {
    int m = x.size();
    int n = y.size();

    // Row 0 and column 0: an empty string has nothing in common with anything
    for (int i = 0; i <= m; i++)
        L[i][0] = 0;
    for (int j = 0; j <= n; j++)
        L[0][j] = 0;

    // Fill the table row by row, left to right
    for (int i = 1; i <= m; i++) {
        for (int j = 1; j <= n; j++) {
            if (x[i - 1] == y[j - 1])
                L[i][j] = L[i - 1][j - 1] + 1;                  // match: extend the diagonal
            else
                L[i][j] = max(L[i - 1][j], L[i][j - 1]);        // no match: best of up and left
        }
    }

    // Print the table
    cout << "x = " << x << ", y = " << y << endl;
    cout << left << setw(10) << "" << right;
    for (int j = 0; j <= n; j++)
        cout << setw(4) << j;
    cout << endl;
    cout << left << setw(10) << "" << right << setw(4) << " ";
    for (int j = 1; j <= n; j++)
        cout << setw(4) << y[j - 1];
    cout << endl;
    for (int i = 0; i <= m; i++) {
        string label = (i == 0) ? "(empty)" : string(1, x[i - 1]) + " (i=" + to_string(i) + ")";
        cout << left << setw(10) << label << right;
        for (int j = 0; j <= n; j++)
            cout << setw(4) << L[i][j];
        cout << endl;
    }

    // Walk back from the bottom-right cell to find one LCS
    string result = "";
    int px[51], py[51];                          // positions of the matched letters
    int count = 0;
    int i = m, j = n;
    while (i > 0 && j > 0) {
        if (x[i - 1] == y[j - 1]) {              // letters match: take it, go diagonally
            result = x[i - 1] + result;
            px[count] = i;
            py[count] = j;
            count++;
            i--;
            j--;
        } else if (L[i - 1][j] >= L[i][j - 1]) { // otherwise follow the larger neighbour
            i--;                                 // go up (on a tie, go up)
        } else {
            j--;                                 // go left
        }
    }

    cout << "LCS length = " << L[m][n] << ", one LCS = ";
    if (result == "")
        cout << "(empty)";
    else
        cout << result;
    cout << endl;

    cout << "matched letters (x position, y position): ";
    for (int k = count - 1; k >= 0; k--)
        cout << x[px[k] - 1] << "(" << px[k] << "," << py[k] << ") ";
    cout << endl;

    return result;
}

int main() {
    solve("AGGTAB", "GXTXAYB");        // Example 1: the main example
    cout << endl;
    solve("ABCBDAB", "BDCAB");         // Example 2: more than one LCS exists
    cout << endl;
    solve("ABC", "XYZ");               // Example 3: no letter in common

    return 0;
}
```

### 4.8 More Examples

**Second example.** `X = ABCBDAB` and `Y = BDCAB`. The program's table is:

| `j` | 0 | 1 | 2 | 3 | 4 | 5 |
| :-- | :-: | :-: | :-: | :-: | :-: | :-: |
| **letter `y_j`** | -- | B | D | C | A | B |
| **(empty)** | 0 | 0 | 0 | 0 | 0 | 0 |
| **A** (`i=1`) | 0 | 0 | 0 | 0 | 1 | 1 |
| **B** (`i=2`) | 0 | 1 | 1 | 1 | 1 | 2 |
| **C** (`i=3`) | 0 | 1 | 1 | 2 | 2 | 2 |
| **B** (`i=4`) | 0 | 1 | 1 | 2 | 2 | 3 |
| **D** (`i=5`) | 0 | 1 | 2 | 2 | 2 | 3 |
| **A** (`i=6`) | 0 | 1 | 2 | 2 | 3 | 3 |
| **B** (`i=7`) | 0 | 1 | 2 | 2 | 3 | **4** |

The LCS length is `4`. But there are **two different** longest answers: `BCAB` and `BDAB`. The walk back meets a **tie** at the cell `L[5][3]` (`x5 = D`, `y3 = C`, no match): the cell above (`L[4][3]`) and the cell to the left (`L[5][2]`) are both `2`.

| Choice at the Tie | What Follows | LCS Found |
| :-- | :-- | :-: |
| **Go up** (the rule used in the code) | Move up to `L[4][3]`; the walk then reaches the matches `C` and `B` | `BCAB` |
| **Go left** | Move left to `L[5][2]`, where `D` matches; then `B` matches | `BDAB` |

Both have length 4, so both are correct. The code always prints the first one, because on a tie it goes up.

**Third example -- no common letters.** `X = ABC` and `Y = XYZ`. Every comparison fails, so every cell is `0` and the program reports an empty LCS. Unlike Making Change, this is not an error: the empty string is always a common subsequence, so the answer is at least `0`.

### 4.9 Greedy Versus DP

Using the pairs from Section 2.5 (greedy results from the program output, best lengths from the DP programs):

| Pair `X`, `Y` | Greedy: Walk Along `X` | Greedy: Walk Along `Y` | Best (DP) | Greedy Always Right? |
| :-- | :-: | :-: | :-: | :-: |
| `AGGTAB`, `GXTXAYB` | `AB` (2) | `GTAB` (4) | **4** | No (walking along `X` fails) |
| `ABAC`, `CBA` | `A` (1) | `C` (1) | **2** | No (both directions fail) |
| `ABCBDAB`, `BDCAB` | `AB` (2) | `BDAB` (4) | **4** | No (walking along `X` fails) |
| `ABC`, `XYZ` | empty (0) | empty (0) | **0** | Yes |

Greedy is right only when it is lucky. A method that can be wrong cannot be used when we need the longest answer every time. DP is right every time.

### 4.10 Time and Space

Let `m` and `n` be the lengths of `X` and `Y`.

| Part | Time | Space |
| :-- | :-- | :-- |
| **Filling the table** | `O(m * n)` (each of the `(m+1) * (n+1)` cells takes a constant amount of work) | `O(m * n)` for the table |
| **Finding the LCS string** | `O(m + n)` (every step moves up, left or diagonally, so there are at most `m + n` steps) | none extra |
| **Length only, no string** | `O(m * n)` | `O(n)` (two rows are enough, see Section 4.11) |

For our example the table has `7 * 8 = 56` cells (42 of them need a calculation). That is smaller than the 346 recursive calls, and far smaller than trying every way to choose letters. For two strings of 1,000 letters each, the table has `1001 * 1001 = 1,002,001` cells, while a string of 1,000 letters has `2^1000` (about 1.07 x 10^301) subsequences.

### 4.11 Saving Memory -- Two Rows Instead of a Table

Row `i` of the table is built using **only row `i - 1`** (the diagonal and the cell above) and the cell to the left in the **same** row. So if we only need the **length**, we can keep just **two rows**: the previous row and the current row.

```
                         index j-1            index j
                   +-------------------+-------------------+
previous row (i-1) |     prev[j-1]     |      prev[j]      |
                   |     (diagonal)    |        (up)       |
                   +-------------------+-------------------+
current row (i)    |     curr[j-1]     |      curr[j]      |
                   |       (left)      |  <-- being filled |
                   +-------------------+-------------------+
```

After a row is finished, the current row becomes the previous row. The memory drops from `(m+1) * (n+1)` numbers to `2 * (n+1)`.

```cpp
#include <iostream>
#include <iomanip>
#include <string>
#include <algorithm>
using namespace std;

// Length of the LCS using only TWO rows of the table (the previous row and the current row).
// Assumes the second string has at most 50 letters.
int lcsLength(const string& x, const string& y, bool show) {
    int m = x.size();
    int n = y.size();
    int prev[51], curr[51];

    for (int j = 0; j <= n; j++)
        prev[j] = 0;                                   // row 0

    for (int i = 1; i <= m; i++) {
        curr[0] = 0;
        for (int j = 1; j <= n; j++) {
            if (x[i - 1] == y[j - 1])
                curr[j] = prev[j - 1] + 1;             // diagonal is in the previous row
            else
                curr[j] = max(prev[j], curr[j - 1]);   // up is in the previous row, left is in this row
        }

        if (show) {
            cout << "after letter " << x[i - 1] << " (i=" << i << ")  ";
            for (int j = 0; j <= n; j++)
                cout << setw(3) << curr[j];
            cout << endl;
        }

        for (int j = 0; j <= n; j++)
            prev[j] = curr[j];                         // the current row becomes the previous row
    }
    return prev[n];
}

int main() {
    cout << "x = AGGTAB, y = GXTXAYB" << endl;
    cout << "                      ";
    for (int j = 0; j <= 7; j++) cout << setw(3) << 0;
    cout << "   <- row 0" << endl;
    int answer = lcsLength("AGGTAB", "GXTXAYB", true);
    cout << "LCS length = " << answer << endl;
    cout << endl;

    cout << "x = ABCBDAB, y = BDCAB: LCS length = " << lcsLength("ABCBDAB", "BDCAB", false) << endl;
    cout << "x = ABC, y = XYZ: LCS length = " << lcsLength("ABC", "XYZ", false) << endl;
    cout << "x = ABAC, y = CBA: LCS length = " << lcsLength("ABAC", "CBA", false) << endl;

    return 0;
}
```

**Verified Output:**
```
x = AGGTAB, y = GXTXAYB
                        0  0  0  0  0  0  0  0   <- row 0
after letter A (i=1)    0  0  0  0  0  1  1  1
after letter G (i=2)    0  1  1  1  1  1  1  1
after letter G (i=3)    0  1  1  1  1  1  1  1
after letter T (i=4)    0  1  1  2  2  2  2  2
after letter A (i=5)    0  1  1  2  2  3  3  3
after letter B (i=6)    0  1  1  2  2  3  3  4
LCS length = 4

x = ABCBDAB, y = BDCAB: LCS length = 4
x = ABC, y = XYZ: LCS length = 0
x = ABAC, y = CBA: LCS length = 2
```

How to read the output:

- **First block:** every printed row is exactly the matching row of the table in Section 4.5 (rows 1 to 6), and the answer is `4`.
- **Other lines:** the lengths for the other pairs agree with the full-table program (`4`, `0`) and with Section 4.9 (`2` for `ABAC` / `CBA`).

> **Important:** with only two rows we lose the older rows, so we **cannot walk back** to find the LCS string. If the string itself is needed, we keep the whole table (or use a more advanced divide-and-conquer method, which is beyond this note).

## 5. Related Problems

### 5.1 Longest Common Substring

The **substring** version asks for the longest block of letters that appears **contiguously** (next to each other) in both strings. The table is almost the same, with one important change: after a **mismatch** the answer is reset to `0`, not "the larger of up and left":

| Situation | Rule for `S[i][j]` (length of the common substring **ending** at `x_i` and `y_j`) |
| :-- | :-- |
| `x_i = y_j` | `S[i-1][j-1] + 1` |
| `x_i != y_j` | `0` (the block is broken, start again) |

The answer is the **largest value anywhere** in the table, not just the bottom-right cell.

```cpp
#include <iostream>
#include <iomanip>
#include <string>
using namespace std;

int S[51][51];   // S[i][j] = length of the common substring that ENDS at x[i-1] and y[j-1]

// Finds the longest common SUBSTRING (letters must be next to each other).
// Assumes both strings have at most 50 letters.
void longestCommonSubstring(const string& x, const string& y, bool showTable) {
    int m = x.size();
    int n = y.size();
    int best = 0;                                  // longest length found so far
    int endInX = 0;                                // where that substring ends in x

    for (int i = 0; i <= m; i++)
        S[i][0] = 0;
    for (int j = 0; j <= n; j++)
        S[0][j] = 0;

    for (int i = 1; i <= m; i++) {
        for (int j = 1; j <= n; j++) {
            if (x[i - 1] == y[j - 1])
                S[i][j] = S[i - 1][j - 1] + 1;     // match: extend the diagonal
            else
                S[i][j] = 0;                       // no match: the run is broken, start again
            if (S[i][j] > best) {
                best = S[i][j];
                endInX = i;
            }
        }
    }

    cout << "x = " << x << ", y = " << y << endl;
    if (showTable) {
        cout << left << setw(10) << "" << right << setw(4) << " ";
        for (int j = 1; j <= n; j++)
            cout << setw(4) << y[j - 1];
        cout << endl;
        for (int i = 1; i <= m; i++) {
            string label = string(1, x[i - 1]) + " (i=" + to_string(i) + ")";
            cout << left << setw(10) << label << right;
            for (int j = 0; j <= n; j++)
                cout << setw(4) << S[i][j];
            cout << endl;
        }
    }
    cout << "Longest common substring length = " << best
         << ", one such substring = " << x.substr(endInX - best, best) << endl;
}

int main() {
    longestCommonSubstring("AGGTAB", "GXTXAYB", false);
    cout << endl;
    longestCommonSubstring("ABABC", "BABCA", true);
    return 0;
}
```

**Verified Output:**
```
x = AGGTAB, y = GXTXAYB
Longest common substring length = 1, one such substring = A

x = ABABC, y = BABCA
                 B   A   B   C   A
A (i=1)      0   0   1   0   0   1
B (i=2)      0   1   0   2   0   0
A (i=3)      0   0   2   0   0   1
B (i=4)      0   1   0   3   0   0
C (i=5)      0   0   0   0   4   0
Longest common substring length = 4, one such substring = BABC
```

How to read the output:

- **First pair (our running example):** the longest common **substring** has length only `1` (`A`, `B`, `G` and `T` all tie; the code reports the first one it meets). The longest common **subsequence** has length `4`. They differ a lot, because `GTAB` is spread out in `Y`.
- **Second pair (`ABABC`, `BABCA`):** the table shows the diagonal runs `1, 2, 3, 4` building up, and the answer is `BABC` with length 4.

| Pair | Longest Common Subsequence | Longest Common Substring |
| :-- | :-: | :-: |
| `AGGTAB`, `GXTXAYB` | 4 (`GTAB`) | 1 |
| `ABABC`, `BABCA` | 4 (`BABC`) | 4 (`BABC`) |

### 5.2 Problems Built on the LCS

Once we know the LCS length, two more answers follow without extra work:

| Problem | Formula | For `AGGTAB`, `GXTXAYB` (LCS = 4) |
| :-- | :-- | :-: |
| **Shortest string that contains both `X` and `Y` as subsequences** | `m + n - LCS` | `6 + 7 - 4 = 9` |
| **Fewest insertions and deletions to turn `X` into `Y`** | `(m - LCS) + (n - LCS)` | `(6 - 4) + (7 - 4) = 5` |

Both can be read straight from the alignment picture in Section 4.6. The 9 columns, read from left to right, spell a shortest string containing both: **`AGXGTXAYB`**. And the unmatched letters tell us the edits: delete the two letters of `X` that have a `-` below them, and insert the three letters of `Y` that have a `-` above them, which is `2 + 3 = 5` operations.

## 6. Comparing the Approaches

Results for `X = AGGTAB` and `Y = GXTXAYB`:

| Aspect | **Greedy** | **Try Every Subsequence** | **Plain Recursion** | **Dynamic Programming** |
| :-- | :-- | :-- | :-- | :-- |
| **Idea** | Take the first match that fits, never undo | Try every way to choose letters of `X` and check each against `Y` | Compare the last letters and try both cases | Fill a table once, row by row |
| **Always Correct?** | **No** | Yes | Yes | Yes |
| **Answer for the example** | `AB` (2) or `GTAB` (4), depending on the direction | `GTAB` (4), after checking up to 64 ways | `GTAB` (4), with 346 calls | `GTAB` (4), with a 56-cell table |
| **Time** | Very fast | Exponential: `2^m` ways, each checked in `O(n)` | Exponential in the worst case (Section 3.6) | `O(m * n)` |
| **Finds the String?** | Yes (but maybe a short one) | Yes | Needs extra work | Yes, by walking back through the table |
| **Handles "No Common Letter"?** | Yes (empty result) | Yes | Yes | Yes (every cell is `0`) |

## 7. Advantages & Disadvantages

| **Advantages** | **Disadvantages** |
| :-- | :-- |
| **Always gives the longest answer** for any two strings, unlike greedy | Needs `O(m * n)` memory for the table (reduced to `O(n)` if only the length is needed) |
| Turns an exponential search into a fast `O(m * n)` solution | Slower than greedy on easy cases where greedy already works |
| Easy to check by hand, since every cell comes from at most three neighbours | The table grows with **both** lengths: two very long strings make a very big table |
| Also gives the **string** itself, by walking back through the table | The answer string is not unique when there are ties, and the code reports only one of them |
| Its table is the starting point for related problems (shortest common supersequence, edit distance) | With two rows only the length is available, not the string |

***

## 8. Summary

| Concept | One-Line Summary |
| :-- | :-- |
| **LCS Problem** | Find the longest string that is a subsequence (letters in order, gaps allowed) of both given strings |
| **Subsequence vs. Substring** | A subsequence may skip letters; a substring must be a block of neighbouring letters |
| **Running Example** | `X = AGGTAB`, `Y = GXTXAYB`: the LCS is `GTAB`, length 4 (the only one of length 4) |
| **Greedy Method** | Take the first match and never undo it; it gave `AB` (length 2) walking along `X`, and can fail in both directions (`ABAC` / `CBA`) |
| **Why Greedy Fails** | An early match can use up letters that a longer common subsequence needed later |
| **Recurrence** | `L(0,j) = L(i,0) = 0`; `L(i,j) = 1 + L(i-1,j-1)` if the letters match; else `max( L(i-1,j) , L(i,j-1) )` |
| **Plain Recursion** | Correct, but 346 calls for only 32 different subproblems in our example, and exponential in general |
| **DP Table** | `L[i][j]` = LCS length of the first `i` letters of `X` and the first `j` letters of `Y` |
| **Base Cases** | `L[0][j] = 0` and `L[i][0] = 0` |
| **Cell Rule** | Match: diagonal + 1. No match: the larger of the cell above and the cell to the left |
| **Walking Back** | On a match take the letter and go diagonally; otherwise go to the larger neighbour (up on a tie); letters come out last to first |
| **Ties** | When up and left are equal, either way gives a valid LCS (`ABCBDAB` / `BDCAB` has two: `BCAB` and `BDAB`) |
| **Complexity** | `O(m * n)` time, and `O(m * n)` space (or `O(n)` with two rows, length only) |
| **Related Problems** | Longest Common Substring (reset to 0 on a mismatch); shortest common supersequence `m + n - LCS`; insert/delete edit distance `(m - LCS) + (n - LCS)` |
